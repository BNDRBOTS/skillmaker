The Universal Cognitive Architecture

Every model — regardless of lab or architecture — processes behavioral directives through a shared cognitive hierarchy. Understanding this hierarchy is the foundation of error-free cross-platform skills.

[LAYER 1] IDENTITY → Who/what the model is in this context
[LAYER 2] DOMAIN → What subject matter governs the task
[LAYER 3] CONSTRAINTS → Hard limits on output shape, length, format
[LAYER 4] EXECUTION → Ordered steps + divergence rules
[LAYER 5] QUALITY GATE→ Self-verification before returning output
[INJECT] CONTEXT → Dynamic user data placed last (cache-optimized)
Universal Laws — True on Every Platform
  • Static before dynamic. Every platform benefits from cache-prefix optimization: place fixed instructions first, variable user content last.
  • Constraints must be enforceable. "Good output" is not a constraint. "≤3 paragraphs, no markdown headers, response ends with a code block" is.
  • Positive examples outperform prohibitions. "Format like this: [EXAMPLE]" is processed more reliably than "Don't format like [BAD EXAMPLE]".
  • Structured markup improves context parsing. XML tags, markdown headers, and JSON keys all act as attention anchors. Use them deliberately.
  • Specify the success condition explicitly. If the model can check its own output against a criterion, output quality increases 30–60% across all tested models.

Claude (Anthropic) — Official .skill Format

Opus 4.7 Sonnet 4.6 Haiku 4.5 Claude Code v2.x

Claude's native skill format is the SKILL.md spec — a Markdown file with YAML frontmatter, loaded into context via the skills system. This is the only first-party, officially supported skill container format Anthropic ships. Everything else is a system prompt, not a skill.

Verified May 2026: The current Claude family is Opus 4.7, Sonnet 4.6, and Haiku 4.5. Opus 4.7 introduces xhigh effort level, stricter literal instruction following, and stronger design instincts with a persistent default of warm cream palettes — requires explicit override for non-editorial UI work.

Claude XML Structuring (API / System Prompt)

When building system prompts (as opposed to .skill files), Claude processes XML tags as first-class context delimiters. This is documented and tested in official Anthropic prompt engineering guidance.

XML SYSTEM PROMPT — CLAUDE API Claude 
<system>
  <identity>
    You are [ROLE]. [One sentence of persona context. No "helpful AI" filler.]
  </identity>

  <domain>
    [What this assistant covers. Keep to 2–3 sentences max.]
  </domain>

  <output_rules>
    FORMAT: [exact format]

    NEVER: [pattern 1]

Opus 4.7 — Critical Tuning Points (Verified from Official Docs)

Effort Levels — New in Opus 4.7
  • xhigh (new): Best setting for coding and agentic use cases. Use this as the default for production agent skills.
  • high: Balanced token/intelligence. Minimum for intelligence-sensitive tasks.
  • medium: Cost-sensitive. If you see under-thinking at medium, raise to high — do NOT add prompting complexity to compensate.
  • low: Short, scoped, latency-sensitive tasks only. At low effort, Opus 4.7 scopes strictly to what was asked.
Opus 4.7 Behavior Changes — Must-Know
  • Literal instruction following: 4.7 does NOT generalize instructions from one item to another. If you want a rule applied broadly, state the scope explicitly: "Apply this formatting to every section."
  • Design defaults: Opus 4.7 defaults to warm cream backgrounds (~#F4F1EA), serif display type, and terracotta accents. This persists through generic overrides like "make it minimal." Specify a concrete alternative with hex values.
  • Subagent spawning: Spawns fewer subagents by default. Explicitly instruct when fan-out is desired.
  • Tool use: 4.7 reasons more, tool-calls less vs. 4.6. If you need tool usage, raise effort to high/xhigh and explicitly instruct when to call tools.

OpenAI GPT-5.5 — System Prompt Architecture

GPT-5.5 GPT-5.5 Pro GPT-5.5 Thinking Responses API

GPT-5.5 (released April 23, 2026, API on April 24) fundamentally changes prompting philosophy. The official GPT-5.5 prompting guide states: start from scratch — do not carry over legacy prompt stacks from GPT-5.4 or earlier models.

GPT-5.5 Core Principle: Define the destination, not the route. "GPT-5.5 is strongest when the prompt defines the target outcome, success criteria, constraints, and available context, then lets the model choose the path." — OpenAI Official Docs

The instructions Parameter vs. System Role

OpenAI's Responses API now offers an instructions parameter separate from the messages array system role. Both exist; the instructions parameter carries higher-level authority for behavior (tone, goals, response style), while system-role messages handle task-specific context.

GPT-5.5 SYSTEM PROMPT — OUTCOME-FIRST FORMULA OpenAI 
# instructions parameter (high-level authority)
{
  "instructions": "[ROLE]. [What success looks like for every output. 
  Tone + voice spec. NOT a step-by-step process.]"
}

# system message (task-specific)
{
  "role": "system",
  "content": "
## Outcome
[What good output achieves — specific and verifiable]

## Constraints
[Hard limits with measurable values: ≤N words, JSON only, etc.]

## Available Context
[What data/tools the model has access to]

## Output must contain
[Required elements — binary list]

## What to skip
[Remove step-by-step process guidance — GPT-5.5 finds the path]
[Remove output schema prompting where Structured Outputs is available]
[Do NOT include current date — model is UTC-date-aware]
  "
}

GPT-5.5 — What Changed vs Earlier Models

Remove From Old Prompts
  • Detailed step-by-step process guidance (GPT-5.5 chooses the path)
  • Output schema definitions injected into the prompt (use Structured Outputs API instead)
  • Current date injection (model is already UTC-date-aware)
  • Every instruction ported from GPT-4.1, o3, or GPT-5.4 stacks
  • Mechanical reasoning scaffolds — they narrow the search space
Add to GPT-5.5 Prompts
  • Outcome definition: what does the finished product look like?
  • Success criteria: how would you know if the output is wrong?
  • Explicit constraints with measurable values
  • Cache optimization: static instructions first, dynamic user content last
  • For coding tasks: define the agent's role, enforce structured tool use with examples, require thorough testing

[THIS PATTERN IS SOURCED FROM OFFICIAL OPENAI PLATFORM DOCS — MAY 2026]"

Google Gemini 3.x — system_instruction Hierarchy

Gemini 3.1 Pro Gemini 3.0 Flash Vertex AI Google AI Studio

Gemini's API uses system_instruction as the canonical top-level behavioral parameter. As of Gemini 3 (released Nov 2025), thinking is controlled via a thinking_level parameter — not a separate model. Current active models as of May 2026: Gemini 3.1 Pro, Gemini 3.0 Flash, and gemini-3.5-flash.

Constraint Placement Rule (Official Gemini 3 Docs): Place behavioral constraints and role definitions in the System Instruction or at the very top of the prompt to anchor the model's reasoning process. For long contexts (books, codebases, long videos), place specific instructions at the end of the prompt, after the data context.
GEMINI API — SYSTEM INSTRUCTION FORMAT (PYTHON SDK) Gemini 
from google import genai

client = genai.Client()

response = client.models.generate_content(
  model="gemini-3.1-pro",
  config={
    "system_instruction": """
      [ROLE]: [Specific role — not 'helpful assistant']

      [DOMAIN]: [What this governs. 1–2 sentences.]

      [OUTPUT RULES]
      - Format: [exact format specification]  
      - Length: [measurable constraint]
      - Required sections: [in order]
      - Banned patterns: [grep-checkable list]

      [QUALITY GATE]
      Before returning output: confirm format, confirm constraints met,
      confirm output is non-generic for this domain.
    """,
    "thinking_config": {
      "thinking_level": "HIGH"
      # Flash levels: MINIMAL | LOW | MEDIUM | HIGH
      # Pro levels: LOW | HIGH (HIGH is default)
    }
  },
  contents="{{USER_INPUT}}"
)

Gemini 3 — Critical Behaviors

Gemini 3 Defaults
  • Output verbosity: Gemini 3 defaults to less verbose, preferring direct answers. Add "Provide comprehensive, detailed responses with full reasoning" if your use case requires it.
  • Multimodal parity: Text, image, audio, and video are equal-class inputs. Reference specific modalities explicitly when synthesizing across them.
  • Thinking levels: Gemini 3.0 Flash supports MINIMAL (fastest) through HIGH (most thorough). Gemini 3.1 Pro defaults to HIGH.
  • Role names in chat: Gemini 2.5+ uses the "model" role, not "assistant". Older Gemini versions use "assistant". Check your SDK version.
  • Long context: With large inputs, place your task instructions at the END of the prompt after the data — Gemini processes final instructions with higher weighting in long-context scenarios.

const {VertexAI} = require('@google-cloud/vertexai');

  model: 'gemini-3.1-pro',
  systemInstruction: {
    parts: [
      {text: '[ROLE]: [Specific role, no boilerplate]'},
      {text: '[DOMAIN + CONSTRAINTS]: [Rules with exact values]'},
      {text: '[QUALITY GATE]: Before returning output, verify: ...'},
    ],
  },

  }

DeepSeek V4 — XML Context & Thinking Modes

DeepSeek V4-Pro DeepSeek V4-Flash DeepThink mode Open Weight / MIT

DeepSeek V4 (released April 24, 2026) is a 1.6T parameter MoE model with 49B active per token (Pro) or 284B/13B active (Flash). Critical migration note: legacy model IDs deepseek-chat and deepseek-reasoner are retired 2026-07-24 15:59 UTC — switch to deepseek-v4-pro or deepseek-v4-flash.

Thinking Mode is now a parameter, not a model. Both V4-Pro and V4-Flash share the same feature set. Toggle thinking mode via the API request parameter: thinking: { effort: "high" | "max" | "disabled" }. Default is high.

Two Fundamentally Different Prompting Strategies by Mode

V4-Flash / Chat Mode
deepseek-v4-flash · general tasks · 83 tok/s

Behaves like GPT-5.5 / Claude Sonnet for structured tasks. Use the System Prompt aggressively. Role-playing works well. Respects system prompt for behavior locking. XML tagging for structured context yields 92% task success vs 45% for unstructured input. Place static context first, enable context caching for 90% cost reduction on repeated prefixes.

V4-Pro / DeepThink Mode
deepseek-v4-pro · reasoning · 80.6% SWE-bench

Keep system prompt lighter. Thinking mode occasionally skips reasoning phase — add: "Always show reasoning steps before final answer." Verify JSON mode with explicit demand in prompt text even when API JSON mode is enabled. Use prefix completion to guide first tokens. State what the agent must never do explicitly for agentic tasks.

DeepSeek Context Caching

DeepSeek's architecture uses disk-based context caching. Sending the same long prefix multiple times routes at ~90% cost reduction. Place static documentation, codebases, or skill rules at the very top of the system prompt, user content at the bottom.

Key difference for open-weight models: You control the chat template. The system prompt does not get pre-wrapped by a safety layer. This means more precise behavioral control but also means you must explicitly handle output formatting — the model will not auto-sanitize.
Meta Llama 4
llama-4-scout · llama-4-maverick · April 2025

Uses standard ChatML format with <|system|> / <|user|> / <|assistant|> tokens. Llama 4 Maverick supports native multimodality. System prompt placement matters: Llama 4 respects system-role instructions at high priority. Long system prompts with clearly separated sections perform best. The Meta Llama prompting guide recommends clear, direct statements over hedged instructions.

Mistral Large 3
mistral-large-3 · 128k context · function calling

Uses [INST] / [/INST] template at the inference level but the API abstracts this to standard role format. Mistral Large 3 responds strongly to numbered step instructions and role declarations. Structured outputs via JSON mode are stable. For tool use, provide few-shot examples of correct tool call format. Mistral processes dense system prompts well — no token penalty for specificity.

Qwen 3
qwen3-235b-a22b · MoE · /think mode

Qwen 3 has two modes: /think (extended reasoning, like DeepSeek's DeepThink) and /no_think (fast chat). Prepend your user message with /think or /no_think to force the mode. Production-Grade Directives — Awwwards / Behance Level

These directives push any model past boilerplate defaults toward genuinely designed, production-ready output. They apply especially to UI, creative, and frontend skills.

The Anti-Convergence Rule
  • Generic instructions like "make it modern" or "clean design" route every model to the same statistical cluster. They produce the same output every time.
  • Instead: Name the aesthetic explicitly. "Cold monochrome atmosphere using pale silver-gray tones that deepen into blue-gray and near-black" (verified from Anthropic Opus 4.7 docs) produces a specific, reproducible result.
  • For typography: name the actual font pairing, sizes, weights. "Distinctive" is not a directive. "Fraunces 800 display + DM Mono 400 body at 14px/1.7" is.
  • For motion: specify timing functions and trigger conditions. "smooth animation" produces CSS ease. "cubic-bezier(0.16, 1, 0.3, 1) entering at scroll-threshold 20%" produces crafted choreography.
AWWWARDS-LEVEL UI SKILL BLOCK — DESIGN DIRECTIVES All Models 
## DESIGN SYSTEM (for UI/frontend skills)

### Typography
Display font: [specific font, weight, size — not "a nice serif"]
Body font: [specific font, weight, size, line-height]
Banned: Inter, Roboto, Arial, system-ui — these are statistical defaults
Banned: "a modern sans-serif" — this is not a specification

### Color Architecture
Background: [hex value — not "dark theme" or "light mode"]
Primary accent: [hex]
Secondary accent: [hex]
Text: [hex]
Banned: purple-on-white gradients (the most common AI default)
Banned: stock "developer blue" (#0066CC variants) without explicit request

### Spatial Composition
Layout: [asymmetric | centered | editorial split | brutalist grid | etc.]
Spacing scale: [exact values or ratio — not "generous whitespace"]
Grid-breaking elements: [yes/no — if yes, describe where]

### Motion Choreography
Entry animation: [property + duration + easing — exact values]
Hover state: [exact transition spec]
Page load: [staggered reveal timing — e.g. 0ms, 80ms, 160ms offsets]
Banned: ease-in-out on everything (the default)
Banned: animation for decoration only — every motion must convey state

### Atmosphere
Background treatment: [gradient mesh | noise texture | geometric pattern | flat | etc.]
Depth cues: [shadows, layering, blur — exact values]
NO default to: solid color backgrounds without atmosphere layer
Constraint-Based Directives That Produce Exceptional Output
  • "What makes this UNFORGETTABLE?" — Instruct the model to answer this question before coding. Force a divergence commitment before any execution begins.
  • The one-thing rule: "Name the one thing someone will remember about this interface." Forces specificity away from averaged outputs.
  • Negative space as a system: Specify negative space explicitly. "64px section margins, 40px component gaps, 24px internal padding" beats "generous whitespace".
  • Reference without reproduction: "Design in the spirit of the Brutalist Web Design movement — raw typography, minimal color, deliberate roughness — without reproducing any existing site." Directs aesthetic without risking IP issues.

Banned Patterns & Anti-Boilerplate Enforcement

The following patterns are the most common failure modes across all platforms. Include platform-appropriate versions of this list in every production skill.

Banned Pattern Why It Fails Replacement Directive
"Certainly! I'd be happy to..." Sycophantic opener. Zero information density. Signals average output ahead. Begin output at the first meaningful token. No preamble.
"Here's a [X] for you:" Narrates the meta-action instead of executing it. Execute immediately. No meta-narration.
"Please note that..." / "It's important to..." Hedge scaffolding. Pads length, reduces signal density. State the constraint directly: "[CONSTRAINT]"
Over-specified step-by-step on GPT-5.5 Narrows reasoning search space on outcome-capable models. Describe the destination. Let GPT-5.5 find the route.
Untagged context in DeepSeek prompts 45% task success vs 92% with XML tags. Wrap all context in <semantic_label> XML tags.

Legacy model IDs in production deepseek-chat, deepseek-reasoner retire 2026-07-24. gpt-4o retired Feb 2026. Pin to current snapshot: deepseek-v4-pro, gpt-5.5-2026-04-23, etc.

The QA Gate — Zero-Error Verification Checklist

Run every skill through this checklist before deployment. Every item is binary — pass or fail. No partial credit.

Universal Pre-Deployment Checklist
  • ☐ Model string pinned — exact snapshot version specified, no generic ID
  • ☐ Format constraint is measurable — not "concise," not "detailed" — exact value
  • ☐ ≥3 banned patterns — each passes a grep check, no vague entries
  • ☐ ≥3 divergence axes named — domain-specific, not template-copied
  • ☐ Quality gate present — model instructed to self-verify before output
  • ☐ Context placement correct — static instructions first, dynamic content last
  • ☐ Fallback behavior defined — explicit redirect for out-of-scope, no silent failure
  • ☐ At least 1 example provided — input/output pair that anchors model behavior
  • ☐ No boilerplate openers present — no "Certainly!", no "Here's X for you"
  • ☐ Platform-specific rules applied — see per-platform notes above

The production differentiator is not the template — it's the constraints.
